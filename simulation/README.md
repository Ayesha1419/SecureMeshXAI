# Simulation interface and limitations

`replay.py` implements a deterministic mitigation decision replay over node-window predictions generated by the model. It emits route-reweighting, rate-limiting, soft quarantine, and isolation **recommendations**. It deliberately does not change a real or simulated mesh's routing state.

The manuscript describes Contiki-NG/Cooja 4.9 with 100 sensors, 1 border router, 3600 s runs, attack onset at 600 s, 10 seeds per scenario and seven routing/flooding attack implementations. Those modified RPL firmware images, Cooja simulation files, serial socket command protocol and ground-truth traces are **not provided in the uploaded manuscript**. They cannot be reproduced responsibly from a generic CSV loader alone. Genuine closed-loop mitigation requires a verified Contiki-NG target, physical routing command handlers, per-hop/forwarding logs and scripted attack scenarios; these artifacts are out of scope of the executable replay shipped here.

The replay is intentionally labeled **offline policy evaluation**, not a demonstration of attack mitigation success, recovery time, packet-delivery ratio or radio-network availability.

Example:
```
python simulation/replay.py --predictions outputs/demo/predictions.json --output outputs/demo/actions.json
```
